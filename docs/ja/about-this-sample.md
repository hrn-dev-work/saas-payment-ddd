# このサンプルについて（非エンジニア向け）

英語版: [../en/about-this-sample.md](../en/about-this-sample.md)

## なぜこの作品があるか

**月額課金・決済会社とのつなぎ込み・既存APIの整理** を頼む側が、次の2点を確かめたいときのためのサンプルです。

1. **同じお知らせは1回だけ** — 決済会社が「支払い完了」を再送しても、契約が二重に始まらない  
2. **役割の分け方** — 決済会社とのやりとりの都合が、アプリ全体に広がらない

Solidpath は **仕事用ポートフォリオのデモ** であり、本物の課金サービスではありません。  
ただし、インターネットに出したときに誰でも書き込める状態にならないよう、**アクセス用の鍵と、お知らせの署名確認**も入れています。

## 操作から見た流れ（申し込みボタンを押すと）

```text
料金ページでプランを選ぶ
        ↓
サーバ側で偽物の決済手続きを始める（カード入力なし・実課金なし。秘密鍵はブラウザに渡さない）
        ↓
「支払い完了」のお知らせと同じ内部処理で契約が有効になる
        ↓
画面に成功メッセージ
```

**同じお知らせ番号** が **正しい署名付き**でもう一度届いた場合（README の手順でエンジニアが再現できます）、サーバは **「すでに処理済み」** と答え、契約を2つ目は作りません。

## 5分で見る評価ポイント

1. 料金ページで申し込み → 成功メッセージを確認する  
2. 可能ならエンジニアに、**署名付き**のお知らせを2回送ってもらう  
3. リポジトリで、業務ルール・処理の流れ・決済つなぎ込み・画面用ルートのフォルダが分かれていることをざっと見る  

## 安全について

- 書き込み用の HTTP API には秘密（APIキーと通知の署名）が必要です。空の `.env` のままインターネットに公開しないでください。  
- 本番用の決済秘密を git に入れていません。手元またはホスティングの環境変数で設定します。  
- ブラウザには申し込み用の API キーを渡しません（サーバ側の処理を使います）。
